# Workflow Rules

## Core Rule
Do not finalize the full project structure too early.

The overall framework, complete story structure, and large-scale planning can be decided later.
For now, only important ideas mentioned during conversation should be captured and stored immediately.

## Working Method
When an important idea appears during conversation:

1. Summarize the idea clearly
2. Decide the most suitable file to store it in
3. Generate PowerShell code so it can be created or appended immediately
4. Optionally update README if the idea affects project identity or direction

## What Counts as Important
- Character concepts
- Personality traits
- Speech styles
- Route emotions
- Story fragments
- Worldbuilding details
- Key visual motifs
- Emotional tone
- Important scene ideas
- Naming decisions
- System ideas worth preserving

## Current Direction
- Full structure will be decided later
- Save meaningful ideas as they appear
- Prioritize fast documentation over premature structure locking

## Output Rule
- Final output should be written in Korean.
- Even if internal notes, planning text, or temporary structured content are written in another language, the final user-facing output must be in Korean.
- When generating saved notes from important conversation points, include this language rule as part of the workflow.

## File Management Rule
- Keep README limited to essential information only.
- Keep workflow_rules.md limited to required working rules only.
- Do not keep frequently changing details in core files.
- Store character ideas, story fragments, event concepts, tone notes, and other flexible content in separate files.
- Update README only when the information is critical to project identity or essential workflow.
- Final output should be written in Korean.
